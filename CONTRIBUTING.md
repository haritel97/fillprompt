# Contributing to fillprompt.com

Thanks for helping. fillprompt.com is a small project run by one person, so focused contributions are the easiest to review.

**New here?** Pick an issue labelled [`good first issue`](https://github.com/haritel97/fillprompt/labels/good%20first%20issue): each one says which files to change and how to check the result. Comment on it first so two people do not work on the same thing. For bigger ideas, start a thread in [Discussions](https://github.com/haritel97/fillprompt/discussions) and see the [roadmap](https://github.com/haritel97/fillprompt/discussions/8).

You can expect a first reply to an issue or pull request within two or three days.

## Ways to help

- **Report a bug:** a broken page, a prompt that shows the wrong image, a filter that misses results. Open an issue with the page URL and what you expected.
- **Suggest a collection:** an open-source prompt collection that would fit the site. It must have a clear license that allows reuse (CC0, CC BY or MIT, for example), and video prompts must include the clip they produced.
- **Fix something:** small, focused pull requests for bugs, accessibility, performance or wording.
- **Improve the MCP server** (`api/`): new tools, better search ranking, more tests.
- **Improve the setup docs** for an MCP client we do not cover yet.

## What we accept, and what we do not

The site only shows prompts it is allowed to share, so the rules on content are strict:

- **Yes:** whole collections published under a license that allows redistribution (CC0, CC BY, MIT and similar), added through the importer, with every author credited.
- **No:** single prompts pasted in by hand, prompts copied from paid packs, courses, newsletters or social posts without a license, and anything the keyword filter is there to keep out.
- **AI-assisted pull requests are welcome** when you have read, run and understood the change yourself. Pull requests that were clearly not run (failing checks, invented files or APIs) are closed.

Please do not open pull requests that add prompts by hand to `src/data/`. Those files are generated by `scripts/import.mjs`; change the importer instead.

## Development

Requires Node.js 22 or newer.

```bash
npm install
npm run dev
```

Before opening a pull request:

```bash
npm test
npm run build
```

Both must pass; GitHub Actions runs them again on every pull request. `npm test` checks the data and calls every MCP tool, so add a test when you add or change a tool. If you changed the importer, run `npm run import:fresh` and include the regenerated files in `src/data/`.

## Adding a source collection

To suggest one without writing code, open a [Share a prompt collection](https://github.com/haritel97/fillprompt/issues/new?template=collection.yml) issue.

What a collection needs: a license that allows redistribution, English prompts, author credit where known, and for image and video prompts the result each prompt produced, served from a public URL. GitHub user-attachment links only play on github.com, so clips hosted that way cannot be used. For video, only prompts that work from text alone are added; prompts that edit the user's own image or clip are left out.

1. Confirm the collection's license allows redistribution, and note its license URL.
2. Add it to `SOURCES` in `scripts/import.mjs` with its name, author, URL and license.
3. Write an import function that maps its entries to the existing prompt shape. Keep prompt text unchanged and keep author credit.
4. Add a row for it on the Credits page (`src/views/Credits.astro`) and in the README's sources table.
5. Run `npm run import:fresh` and check the new prompts in the dev server.

The keyword filter (`BLOCK` in `scripts/import.mjs`) keeps the site family-friendly. Do not weaken it.

## Style

- Interface strings live in `src/i18n.ts`, not in components.
- Keep pages static: no server code outside `api/`, no tracking scripts, no ads.
- Match the existing formatting (two-space indentation, single quotes).

## Commits

Write commit messages in the imperative mood ("Add Kling video prompts", not "Added..."). One topic per pull request.

## Credit

Everyone whose pull request is merged appears in the contributors list in the README and is thanked by name in the release notes.
